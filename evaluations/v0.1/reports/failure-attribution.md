# StoryForge v0.1：Held-out Test 失败归因与评审质量审计

**依据**：2026-10-09 Held-out Test，20 组匿名对照；四份原始评分 g/q/c/ch；第五位仲裁 001/002/012/018；`heldout-unblind-final.json`。本报告不改变已冻结的原始投票、仲裁和解盲结果。

## 1. 主要结论

- **工程验收通过，模型晋升不通过**。Base 样本级多数票获胜 13/20，Adapter 7/20；原始偏好 Base 44、Adapter 28、平局 8；五维均分 Base 3.925、Adapter 3.815。差距是描述性的，20 个样本不足以声称普遍或统计显著的胜负。
- **Adapter 不是全面失效**：在 001、002、003、004、005、012、017 获得样本级胜出。应研究这些成功样本中的对话承接、情绪节制与角色互动，而不是只保留失败案例。
- **评审质量存在明确异常**：q 评审的多个文字理由与当前样本的用户输入错位。此项风险必须独立记录，不能误算为模型错误。原始投票不可静默删除或改写，应开展盲态复核。

## 2. 失败类型与有据可核查的样本

| 类型 | 示例 | 四位评审中的实际描述 | 建议改进方向 |
|---|---|---|---|
| 剧情/人物事实错误 | 000 | 争议侧将允浩称谓和关系混淆、提前相遇；另一侧也有离场事实争议 | 故事事实与人物关系状态检查 |
| 指令动作未执行 | 001 | 一侧把“破窗”改成“冲向大门”；仲裁因此选择另一侧 | 明确动作必须正面处理，成败可变化但不可直接替换 |
| 空间因果冲突 | 002 | 已落锁的浴室门在无解释的情况下被打开 | 物理与空间连续性样本 |
| 用户话语理解偏差 | 003 | 一侧把“因一个女人与兄弟闹翻”的讽刺当成另有女性 | 指令指代与关系语义训练 |
| 臆造玩家心理动机 | 004 | 一侧把解衣对峙无依据地解释为求死 | 玩家自主权门禁与负面样例 |
| 重复/循环生成 | 005、006、009、010、014、015 | 多位评审记录近似台词循环、无效省略号或段落复述；具体侧别依样本不同 | 先排除生成/格式故障，再进行针对性去重复数据建设 |
| 无根据改写时间线 | 015、016 | 凭空引入朝堂弹劾、两天一夜的跪候，与时序不符 | 事件发生条件、时间线约束 |
| 玩家角色越权 | 016、017、018、019 | 擅自代玩家进食、说“不走”、闭眼或改变欲触物品 | 分层扣分：强制决策 > 具体动作 > 未证实的心理 |
| 人物反应转折过快 | 012、017 | 对长期戒备人物的突然软化出现争议 | 用渐进反应替代即时关系翻转 |

**注意**：表中列的是评审者提及的问题主题，并非都指向 Adapter；要归因于 Adapter，必须结合解盲映射逐条确认。某些评审对同一事件给出了相反结论。

## 3. 评审一致性与可靠性风险

### 3.1 q 文件中的潜在错题理由

下列例子均来自相同样本行的“当前用户输入”及 q 文字理由：

- **006**：用户说“我很好，只是因为身边没有我的男人陪着，很孤单”，q 却讨论“真的，是来我这儿的吗？”及“空白省略号”，需核实是否评价了其他回复。
- **008**：用户描述街上被车撞，q 理由却讨论“臭写小说的”身份与江寒之生平。
- **010**：用户提出“我可以帮你……”，q 理由却讨论牵手后入睡。
- **011**：用户请求牵手休息，q 理由却讨论“负责到底”。
- **017**：用户描述元宵喜脉，q 理由却在评价产后“擦干净、歇一歇”。
- **018**：用户请求产后清洁休息，q 理由却在评价“他不在”及纸条情节。

**结论**：存在至少六处高度可疑的理由错位。这证明文字证据不能直接用于这些样本的因果归因；并不能单凭文字错位推定数值评分本身无效。建议复核 q 的全部 20 组输入、回复和评分，并保留复核前原件。

### 3.2 剔除 q 的敏感性分析（诊断，不是正式替换）

| 统计口径 | Base | Adapter | Tie |
|---|---:|---:|---:|
| 冻结四评审原始偏好 | 44 | 28 | 8 |
| 仅 g/c/ch 原始偏好 | 33 | 20 | 7 |

| 统计口径 | Base 五维均分 | Adapter 五维均分 | Base − Adapter |
|---|---:|---:|---:|
| 冻结四评审 | 3.9250 | 3.8150 | +0.1100 |

剔除 q 后，结论方向仍是 Base 领先，但不能据此认定所有评审无偏或推断统计显著性。正式报告仍必须保留四评审冻结原始数据。

## 4. 下一轮 v0.2 数据改进优先级

1. **P0：评价质量先修复**。隔离 q 理由错位风险；设计样本 ID / Prompt hash / 评分正文三重校验；请原评审者盲态复核错位理由，不能参照解盲结果重打分。
2. **P0：玩家自主权与指令遵循**。构造“明确动作不得偷换”“不能代玩家做重大选择”“NPC 可拒绝但必须合理承接”的正反对照样本。
3. **P0：状态和事实一致性**。人物关系、已交付物品、时间线、场景位置及既有禁令形成结构化核对清单。
4. **P1：重复与推理生成故障分离**。区分训练诱发的措辞循环、模型本底问题和推理参数导致的退化；避免将所有重复现象都归因于微调。
5. **P1：角色渐变和有效推进**。保留 Adapter 获胜样本的积极特征，但避免过度迎合和角色突然软化。

## 5. 下一轮训练与测试原则

- 冻结 Baseline v0.1 Adapter、既有 20 条测试集及四评审+仲裁记录。
- **不能再将这 20 条测试集视作下一模型版本的全新未见评测。** 已分析的测试样本可作为诊断集合，但新版本最终验收需要另一套独立的故事级测试集。
- 推荐先通过人工核对、源数据分层、正反例去重和评审一致性改进构建 Dataset v0.4，再考虑是否训练 v0.2。不要单纯加 Epoch 或 rank。
