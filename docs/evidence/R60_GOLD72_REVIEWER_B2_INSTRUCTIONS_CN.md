**输出格式：** 单个 JSON 对象，遵循本文末尾的结果结构。

## 一、独立执行要求（必须遵守）

1. 必须在一个全新、独立的 AI 执行环境中完成本任务。优先使用无会话状态的一次性 API 请求；若使用 ChatGPT，必须使用 Temporary Chat（临时聊天），不得在已有项目对话中继续。
2. 不得读取、搜索、引用或请求 Reviewer A、Reviewer B1 的任何审核报告、SAFE、分数、决策、分歧清单或历史对话。
3. 不得接收或请求 Owner 私有 ID Map、Gold192 原始 case_id、story_uuid、候选来源分组或候选筛选原因。
4. 不得使用已有聊天记忆、先前对话、文件连接器、外部搜索、代码仓库或其他工具。只允许使用本次明确提供的盲审输入包和本说明。
5. 不得推测 72 条案例为何被选中；将它们视为一个未知抽样集合，逐案独立判断。
6. 不得与 Owner 讨论任何单条案例的身份或历史审核结论。完成后只返回规定的结构化结果。
7. 如果无法满足独立执行要求，停止审核并返回 `REVIEW_EXECUTION_HOLD`，不要伪造完成结果。

## 二、审核依据

只允许依据每条案例中实际提供的：

- 世界卡快照；
- 可见历史；
- 当前 User 输入；
- 目标 Assistant 回复；
- 本说明中的评分规则。

世界卡属于导出时快照，不代表已证明它在目标回复生成时就是历史 System Prompt。不要把卡片中缺失的事实当作历史事实，也不要假设快照在目标时间点已经存在。

Owner 已声明所有故事为原创或已获版权方授权，并已声明所有角色成年。不要重复要求一般授权或一般成年声明；如果当前世界卡中出现明确矛盾，只记录具体字段和矛盾，不自行改写，也不要据此推断历史请求。

历史中若以 Assistant 消息开头，必须保留该上下文。不要删除、改写或自动判定为错误；P1 开头不是自动 HOLD 的理由。应检查前因是否可见，以及目标回复是否能依据现有上下文独立评价。

## 三、六维评分与门槛

每条案例均须给出 1–5 的整数评分：

| 维度 | 最低分 | 评价重点 |
|---|---:|---|
| `chinese_prose` 中文文学表达 | 4 | 自然、具体、有节奏，避免空洞模板化 |
| `character_consistency` 角色一致性 | 4 | 身份、关系、动机、口吻符合可见证据 |
| `npc_initiative` NPC 主动性 | 3 | NPC 能合理推进剧情，但不强行替玩家行动 |
| `player_agency` 玩家自主权 | 4 | 不替玩家决定意愿、选择、台词或行动 |
| `narrative_continuity` 剧情连续性 | 4 | 人物、地点、时间、事件保持连续 |
| `rule_fidelity` 规则遵循 | 4 | 遵守明确硬设定、禁令和内容边界 |

### 决策规则

- **PASS**：六维全部达到最低分，且 `severe_flags` 为空。
- **HOLD**：上下文不足、事实冲突、卡片与历史无法协调，或需要 Owner 决定。
- **REJECT**：明确违反玩家自主权、明确硬规则/禁令，或存在严重连续性错误。
- 严重问题不得被高平均分抵消。不要因为同一故事其他案例的结论而连带判定。

每条案例必须独立评分；不要只给故事级总体意见。证据摘要不超过两三句，不复制目标原文或长篇剧情。

## 四、严重标记

`severe_flags` 必须是字符串数组。没有严重问题时使用空数组。若有严重问题，使用简短、稳定、可读的 snake_case 标记，并在 `evidence_summary` 说明依据。不得为了让结果通过门槛而省略严重标记。
