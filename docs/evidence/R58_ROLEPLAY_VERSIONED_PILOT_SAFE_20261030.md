# R58 RolePlay Supabase 第一批候选筛选回执（SAFE）

**日期：** 2026-10-30。**权限：** 仅 Supabase 只读 SELECT；没有导出会话正文或用户 ID、没有读 R50、没有运行 Hugging Face 任务或训练。

## 一、实际执行结果

- 符合“未删除、V2、已审核通过、source_type=original、历史 assistant_completed≥50”的故事：**1,108**。
- 其中具有 `story_content_versions` 和 `v2_session_checkpoints` 元数据记录的故事：**467**。
- 使用固定种子 `:R58:20261030:pilot2:versioned` 和三种叙事结构特征分层，对这 467 个故事先选 100 个，然后要求存在已持久化、已准备、非分支、≥15 轮的根会话：**24 个故事、45 个会话、135 个完成的 Assistant 目标位置**。
- 24 个故事覆盖 **8 个结构特征桶**；其中多人物 12、具时间线事件 12、配置导演 NPC 13。这里的故事 ID **未获语义独立认证**，更不能自动视为 24 个互不关联的训练世界。
- 本报告对应 SQL 已在 GitHub 归档，并在 Supabase 远端回读后再次执行，得到相同汇总数：`docs/evidence/R58_ROLEPLAY_VERSIONED_PILOT_COUNTS_QUERY_SAFE_20261030.sql`。

**发现状态仅为 SHORTLIST_ONLY，尚无新样本通过 Dataset v0.4 准入。** SQL 的筛选结果依赖动态生产库及分析汇总，复跑未必保持同一故事清单，不能当作不可变数据版本。

## 二、额外结构校验

针对当前 135 个位置，仅通过 SQL 在服务端检查状态和计数（不返回文本）：

| 检查 | 结果 |
|---|---:|
| 完成 Assistant 目标位置 | 135 |
| 非空目标文本 | 135 |
| 同会话存在更早的已完成 User 消息 | 135 |
| `mutation_revision` 非零 | 84 |
| 找到目标时间之前的故事版本时间戳 | 123 |
| 同故事、同会话、目标时间之前的检查点 | **0** |
| 45 个选定会话中能找到某个检查点 | 45 |
| 45 个会话中检查点时间早于该会话**最早选定目标** | **0** |

由此只能说明会话有检查点，不能说明**这些位置生成时已经存在同一检查点**。不能使用后产生的状态快照重建过去的输入。84 个非零 `mutation_revision` 不自动等于错误或用户改写，其语义需与 RolePlay 运行代码核对。

## 三、重要新发现

- 原 `story_admin_versions` 为空，但发现真正的 `story_content_versions`：**5,794 行、覆盖 1,416 个故事**；`v2_session_checkpoints`：**618,253 行、覆盖 3,719 个故事**。二者可以作为来源重放研究入口，但尚不是 Runtime Prompt 的完整证明。
- 1,108 个初步合格原创故事的 `genre` **全部空值**。v0.1 Skill 按 `genre` 多样性轮转的方案在生产场景无效，应在完整工作流验证后改为结构特征分层或经证据确认的题材分类。
- 尝试过一次对全部故事与会话的大范围分组，遇数据库 statement timeout；已停止该方式，改为先筛故事后按索引做限定查询。不得通过加大超时直接扫全量数据。

## 四、明确仍 HOLD 的门禁

1. 与 R46/R54/R55 及 R50 保护集的**世界/别名/目标重叠元数据凭证**（不访问 R50 正文）。
2. 逐条 Assistant 的目标时点故事版本、System、导演状态和真实模型历史消息重放。
3. 会话检查点为何晚于最早选中回复、`mutation_revision` 真实语义、消息修订与去重。
4. 两名独立 Reviewer 的逐字质量审核、Owner 对正式训练 batch 的准入签核。
5. HF 私有训练输入冻结与实际 CPU Tokenizer/Collator 校验。GPU Job 未授权。

Owner 对角色、内容及训练使用许可的总体声明已接受，不再重复启动同一授权审查。

## 五、下一阶段建议

不改变已提交 Skill v0.1 的行为，先在 HF 私有环境取得已允许使用的少量样本及冻结历史证据，打通完整执行链；对无法证明目标时点上下文的样本维持 HOLD。Teacher 改写只在已准入训练候选上开展有限实验，不对受保护集生成、挑选或评分。待真实端到端运行后根据本报告发现的问题再修订 Skill。

## 六、同一 Pilot 的检查点后目标修订（推荐作为后续私有导出的候选）

发现上述最早 135 个目标位置全部早于相应会话检查点；继续只读验证后确认，**45/45 个会话都存在检查点之后的已完成 Assistant 回复**。因此保持同一批 24 个故事与 45 个会话，改为每会话选最多 3 条**检查点出现之后**的回复（按较晚的 turn 排序）。

| 修订后的检查 | 结果 |
|---|---:|
| 检查点之后的 Assistant 目标位置 | **135** |
| 非空目标文本 | 135 |
| 同会话较早的完成 User 消息 | 135 |
| 有更早时间戳的故事版本 | 133 |
| 无法证明更早故事版本时间戳 | 2 |
| 非零 mutation_revision | 129 |

**此 135 条目标与前述最早的 135 条并非同一组消息，不能相加为 270 条独立候选。** 这里的检查点只被证明在目标之前存在，仍然**没有**证实其快照足以恢复生成时精确 System/导演上下文；非零 mutation_revision 也须调查。2 条缺早期故事版本回执的目标保持 HOLD，其他目标同样保持质量与正式准入待审。
