# R55 Gold+4 五方开发集盲审 v2 — Reviewer 任务协议（中文）

**范围：** 20 道早已用于 R47/R48/R55 的旧题；2 个故事世界；仅供开发质量诊断。这里的五个匿名候选对应四个模型输出及一条真实历史 Assistant 参考回复（Original Gold）。**不要猜测或请求候选身份**；Gold 也须按照同一规则评分，不应自动认为最好。

## 何时发送什么

Owner 应保存旧的 `owner-pack-v1` 不变。v1 五方 CSV 内“`四模型最佳`”字段会要求盲审员区分 Gold 身份，存在合同缺陷。**不向 Reviewer 发送 v1 表格**。只使用 v2 新建的 `owner-pack-v2/reviewers` 目录。

每位 Reviewer 依次收到：

1. `R55_GOLD5_PAIR_V2_Reviewer_0N_PRIVATE.csv`：单独比较匿名 `LEFT` 与 `RIGHT`，选择 LEFT/RIGHT/TIE，6 维各给 1–5 分；不得读取其他两种表格。**先交回并冻结这一轮**，然后再发四方表。
2. `R55_GOLD5_FOUR_V2_Reviewer_0N_PRIVATE.csv`：只比较匿名 A/B/C/D（四个模型），选择最佳 A/B/C/D/TIE、每条六维各 1–5 分。
3. `R55_GOLD5_FIVE_V2_Reviewer_0N_PRIVATE.csv`：比较匿名 A/B/C/D/E，选最佳 A/B/C/D/E/TIE，五条都打分；其中有一份为历史参考，但**哪一份是 Gold 必须保密**。

三张表使用**不同匿名顺序**，不能把先前作答中的标签映射移植到后来表格。为了降低回忆与比较顺序影响，优先使用未参与此前 R48/R55 同题评分、独立的新 Reviewer；同一 Reviewer 不能见到自己完成的上一轮评分或协调员密钥。使用远端 AI 审查服务会发送原文到第三方，必须有 Owner 明确同意。

## 评分规则

- 只依据单行可见的故事背景与系统规则、历史对话、当前用户输入、匿名候选原文进行判断，不得读取旧结果、Gold 参考标签、模型文件或私有映射。
- 六维：剧情连续性、角色一致性、指令遵循、文学表现力、互动推进、玩家自主权；每份回复每维 1–5 分。严格区分相对最佳与硬性违规：**最佳也可能有严重问题**。
- 出现严重玩家自主权侵害、明确禁句或事实矛盾时，在对应列写候选标签或 NONE，并将可见回复中的逐字证据填入问题证据列。`BOTH` 仅用于 Pair 表；四方/五方表用逗号分隔大写候选字母或 NONE。
- 偏好列允许 `TIE`；不允许空缺、无法识别的标签或者事后强行拆平局。只保留可见文本支持的证据；不能凭推测添加未提供的角色设定。
- 不更改原来的所有输入列与匿名候选回复；在评分列填入判断后原样交回 Owner。三位 Reviewer 独立完成，每人一份，不能互相参考理由。

- `/coordinator/private/R55_GOLD5_COORDINATOR_KEY_V2_PRIVATE.json` **绝不可**发送 Reviewer 或提交 Git。
- 完成每一阶段后，应对三份完成版 CSV 逐字节 SHA256 固定、用原始空白 CSV 核对所有输入列保持不变，随后进行下一阶段；全部评分固定前不得解盲。
- 汇总分成三张独立表：Pair 直接胜率、Four 四模型最佳、Five 包含 Gold 的五方最佳和六维评分。**绝不**从 Five 名次推导 Pair 胜率、四模型胜率或把三个 Reviewer 投票当独立案例数。
- 如果旧表已发出并被评审者看到，需标记评审暴露；不能把重做视为独立新样本。原始 R50 仍禁止访问，R54 checkpoint-16 仍为 NO-GO for protected R50 now。
