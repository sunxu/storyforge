# StoryForge R58 — 高质量中文互动剧情 LoRA 主线（Owner 目标重定向）

日期：2026-11-01。适用：`sunxu/storyforge` Draft PR #7，`r58/roleplay-sft-skill-v01`。

## 0. 唯一目标与优先级

**目标是训练更擅长高质量中文互动剧情的 Qwen LoRA**，重点提升中文文笔、人物/世界与跨轮事实一致性、NPC 主动推进、遵守禁令和玩家自主权。最终以**独立世界、盲评、可复现的模型对照**衡量，而不是以历史请求审计完成度衡量。

Owner 明确：**不需要把任何训练样本认证为原始生产 Provider 请求，也不需要历史生产请求的精确回放。** 完整 HTTP 请求字节、历史部署 SHA、request_id 因果绑定、动态生产路由版本和目标时刻逐字 Prompt 均不是本训练主线准入条件。以前的 G2 字节级审计仅是历史研究，不再执行；既有 G2=HOLD 记录保持历史事实，不能作为新的质量试点是否值得继续的阻塞。

**仍必需：**数据使用权/安全边界、可信来源和版本、上下文自身真实可用性、硬设定与玩家自主权、训练/验证/保留测试间的世界级隔离、不得接触 R50 密封测试、逐条双审、冻结与可复现训练输入、last-assistant-only mask、CPU preflight、付费 GPU 单独授权。这些不是原始生产请求精确回放。

## 1. 两级数据路径，不为扩大数量降低质量

**第一优先：复用已经冻结的 Gold195**（Gold87 + Gold108，原批次不重选、不改原始文件）。从独立授权来源中构建可审的 SFT 样本版本：世界卡/人物/当前用户输入 + 足够且连贯的前置历史 + 当轮高质量目标 Assistant。目标是按质量重审获得可用的 Train/Validation，不为凑 120–160 条而放水。旧 R45 49/15、R46 rank64 七步 checkpoint、v0.2/v0.3 统计是参考基线；原有被 HOLD 的样本不自动解封。

**第二优先：R58 RolePlay 小试点。** 先只处理已选五世界中的剩余四世界（已知 SFT UUID 曝光的一世界继续排除），总候选回复不超过原 Pilot 的 20 条；不得重选新世界/扩样。其来源可以是合法原始 RolePlay 文本加上**明确标记的离线训练上下文编排**，而非声称生产 request byte-exact。先评审原始来源和保护边界，再仅在私有受控环境审阅文本。未知历史 HF Job 不必作为“复现这些历史调用”的任务；但是任何已知训练/开发/保留测试世界污染风险仍要按独立世界/内容交集进行处理，无法确认的对应样本保持 HOLD，不可碰密封题文。

禁止未经审查的 Teacher 自动重写；首个新实验先 `original-only`。以后如测试 Teacher 增益，单独版本记录父源及配方，Teacher-only 不进入 Validation 或密封测试。

## 2. 训练准入应采用新的 Quality Gate，而不是旧 G2 回放门禁

逐条候选需要的条件（独立于旧 `G1/G2` 编号，不得复用旧 PASS 状态）：

1. `SOURCE`：来源权利与冻结版本明确；文本、目标和训练消息之间可追踪，历史上下文内部因果连贯。**不要求原始在线 HTTP 字节或历史部署版本。**
2. `ISOLATION`：以语义世界组件为单位划分 Train/Validation，不跨集合；排除已经确认的 R50/其他保护/最终测试来源和不适合当作独立测试的旧开发题；不读取 R50 题目正文。对不可确认的世界关系作 HOLD。
3. `STRUCTURE`：真实当前 User、正确角色顺序、足够的禁句/承诺/历史、规范 JSONL、末轮 Assistant 目标唯一、目标不使用未来剧情透视；Token 上限 16,384，按 Qwen 实际模板和 Collator 验证。
4. `QUALITY`：两份相互独立、看不到模型身份的评审意见；记录硬事实/禁令、严重代写玩家、NPC 主动推进、中文自然度与剧情张力、角色一致性与重复表达；不单靠总分。严重越权/事实错误直接 REJECT，有争议 HOLD，优秀才 PASS。
5. `FREEZE`：通过者冻结来源哈希、派生转换版本、训练标签掩码核验及 Train/Validation 世界分组；不把旧 DEV/已暴露 Test 当最终独立晋升测试，R50 保护保持隔离。
6. `TRAINING`：只有正式批准的 dataset/config 和 CPU-only preflight 完成后，才请求一次明确的 GPU 运行授权。绝不自动触发 HF Job、付费资源或模型晋升。

旧 `skills/storyforge-roleplay-sft/scripts/r58_intake.py` 的 `history_replay_verified` / `target_time_canon_verified` 是**旧模式代码合同**，不能直接把它们写成 `true` 来绕过。新 Quality Gate 需要另立 schema 和独立测试，或者先获得 Owner 代码变更批准；在这之前不把任何 R58 样本送入 `freeze` 训练入库器。

## 3. 下一轮实际交付顺序

- **A：冻结基线与候选范围。** 复用 Gold195 和原 R45/R46/v0.3 实验资产；只在私有环境处理原始内容，不修改源 Gold；确认现有世界 Train/Val/Test 划分的证据与残余 HOLD。
- **B：先完成小批量质量双审。** 在已有可审 Gold 与四世界试点中，仅对来源和隔离已清楚的记录进行审阅；最多处理 R58 原定 20 条目标；记录 PASS/REJECT/HOLD 与严重玩家自主权/硬事实问题，禁止用模型身份影响判断。
- **C：生成 Quality-v1 候选数据。** 原创目标先行，补齐上下文、异常截断/角色掩码/世界去重检查；明确区分人工确认数据、原始 Gold、Teacher 衍生，不混成一个 Gold。
- **D：CPU 验证后申请 GPU。** 固定 Qwen3.8-27B 与既有 LoRA 基线，比较新数据对文学表达/玩家自主权/互动推进的影响；保留同条件的旧开发集用于回归，R50 不用于调参、选 checkpoint 或 Teacher。
- **E：评审增益。** 先按世界汇总，再按严重错误与文学质量独立汇总；训练 loss 下降不代表质量晋升。失败则回到高价值数据问题，不再追加部署/Provider 溯源查询。
