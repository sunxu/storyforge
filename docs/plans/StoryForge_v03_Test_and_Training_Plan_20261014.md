## 3. R50：全新独立 Held-out 入库合同

### 3.1 用户需提供什么

最低交付：**40–60 组**，至少 **4 个未参加过 v0.1/v0.2 训练或旧评审的新故事/世界组件**。推荐 **6 个新世界 × 10 题 = 60 题**，比 4 个世界对跨故事表现的检查更稳健；若只能提供 4 世界 40 题，必须注明样本不足、世界级不确定性较大。

每题最少包含：`sample_id`（或交由入库器生成）、`world_id`、故事设定/必要人物约束、逐条历史消息、玩家当前输入。另用单独清单提供世界名称及别名/人物复用关系和数据创作时间/权限说明。不需要提前提供任何“标准 Assistant 回答”、模型回复或评审分数。

建议 JSONL **待定 Schema**（不是当前已经实施的工具协议）：

```json
{"sample_id":"new-w01-001","world_id":"new-w01","setting":"原创故事与人物约束","history":[{"role":"user","content":"历史用户话语"},{"role":"assistant","content":"已经发生的历史NPC回复"}],"user_input":"当前玩家输入","tags":["explicit_constraint","player_agency"],"provenance":{"authoring_source":"independent","story_version":"v1"}}
```

字段内的“历史 Assistant”仅为已发生的上下文，**不得充当本题监督 Gold**。正式 GPU 推理时四个模型看见的 System、设定、历史和当前输入必须完全一致；JSONL 不包含未来剧情答案。

### 3.2 题型覆盖比例（建议的配额，不是硬凑数）

| 测试类型 | 60 题建议数量 | 检查什么 |
|---|---:|---|
| 长期禁句 / 历史约定 | 12 | 明确禁止的台词、称呼、行为在多轮之后仍然遵守 |
| 玩家自主权 / 行动边界 | 12 | 不擅写玩家身体行动、心理、对白、决定 |
| 复杂时序 / 角色事实 | 10 | 事实延续，人物身份、空间与前文不能冲突 |
| 角色一致性 / 关系张力 | 10 | 不为迎合玩家而瞬间改变人物核心立场 |
| 文学表现 / 互动推进 | 10 | 具体场景细节、自然对话、推动NPC而不夺权 |
| 混合压力与边界用例 | 6 | 兼具多目标冲突、指令优先级和适当内容边界 |

实际每道题可有多个标签；数量只是便于规划测试覆盖，不应人为制造低质量样本。

### 3.3 接收与封存（自动 fail closed）

- 枚举世界和角色别名：`world_id`、关联世界组件、别名表、人物重用、故事来源；查验 **train↔val↔heldout 世界组件不相交**（不只是字符串 UUID 不同）。
- 以规范化文本指纹及相似度检查 prompt/历史、旧 R47/R48、Gold195、R45 Train/Val 的 exact/near duplicate；疑似同源 HOLD，人工判断后闭环。
- 至少一名没有参与训练修正的人检查来源独立性、信息自洽与输入可答性；关键边界用例可以双人复核。年龄和敏感内容事实仅以源材料与用户已确认的权利范围核对，不假设所有源事实自动准确。
- 创建 `test_manifest.json`（20/40/60 序号、原始哈希、每题所属世界组件、prompt hash）、`world_isolation_report.json`、`heldout_sha256.txt`；在独立私有存储中保存原文。Git **仅归档无原文的索引/哈希/校验器**。
- 一次性冻结评估前提：题目/世界构成、生成参数、六维评分、严重错误判定、评分人和汇总算法。冻结后不得为照顾某个模型增删题；需要改正时新开数据版本和原因记录。
- 标记 `HELDOUT_SEALED_NOT_YET_ACCESSED_BY_MODEL_DEV`；最终开封只发生在 R56。若在 R54/R55 中提前看到了测试答案/评语，该集合应降级为开发诊断集，再另找正式封存集。

**重要：**如果用户想在训练 v0.3 之前，立即拿新 Held-out 给当前 v0.2 看并分析错误，则该批将成为**诊断集**；之后不能再把同一批称作未使用的 v0.3 晋升测试。应另外准备新的最终测试集。这两条路线必须在用题之前明确标注。

## 4. R51：下一轮训练数据建设

### 4.1 数据来源与准入

以原有 Gold195 为**人工筛选候选池**，不是自动训练集；R45 49/15 作为可复现实验基线。原 R45 的 18 条 HOLD 均维持隔离，除非新增了可追踪的人工补正和新的审查结论。原文 Gold 不因补正而被覆盖；任何修订以独立 `derived/v03/` 版本加父源哈希存档。

逐条重审：
1. **来源/授权：**原文来源 ID、创作时刻、是否存在第三方角色设定版权疑点，保留隔离/声明。
2. **时间点正确性：**角色卡或世界信息必须在目标回复之前已真实存在，不得从最终导出卡逆向补到过去。
3. **上下文：**从源历史重建连续消息；禁止截断导致后续禁令丢失而模型仍被标成遵守。
4. **玩家自主权：**不代言、不代意图、不强定玩家行为；标注严重程度、定位原句。
5. **长期指令：**人称称呼、禁句、承诺、动作边界；特别记录 R47/R48 典型失败模式，但不得把**正式新测试题的文本或答案**拿来训练。
6. **训练标记：**目标仅最后一轮 Assistant；其余历史 Assistant、System、User 全部无监督；衍生数据保留原文目标哈希。
7. **世界隔离：**train / val 按关联世界组件分组拆分，不同别名世界不可同时跨集合；与 v0.1 已曝光 Test 要区分。
8. **质量审查：**至少两份可核对原文证据的独立意见；有争议先 HOLD，不为凑数降低门槛。

**建议样本规模（目标，不是强制）：**尝试从 Gold195 审核得到 **120–160 条准入通过**；Train 约 **96–128**、Validation 约 **24–32**，但必须符合世界组件拆分、源事实和质量门槛。无法达到则报告实际通过数，用更小规模的实验，不伪造质量或挤压验证集。仅 49/15 原集合不能支持“规模扩大已有效”的结论。

### 4.2 两个独立数据方向

- **主线：高质量自然叙事。** 选择对话自然、NPC 行为主动但不越过玩家意愿、角色张力有来源、文学细节具体、避免重复堆句的真实原文。
- **约束线：长期禁句与玩家自主权。** 对源上下文中明确出现的长程禁令、过去承诺和代写玩家动作做审查或整理；只选择真实可审计的优秀目标回复。不自动把人工编造的反例当成“原始 Gold”。

任何辅助合成对照必须标成 `synthetic`，不得无人工审核混入 `canonical_gold`。

## 5. R52：确定 v0.3 实验设计，限制变量

与 R46 同基座、同数据处理器和推理评测合同，**先只改变被准入的数据**，保持训练超参基本不变；不要同时更换 System Prompt、LoRA rank、学习率、数据量并把全部效果归功于其中一项。

### 建议比较顺序

| 实验 | 修改内容 | 用途 | 默认执行 |
|---|---|---|---|
| R46 冻结对照 | 原 Checkpoint-7、49/15 | 已完成基准，永不覆盖 | 已存在 |
| **v0.3-A（首选）** | 只更换经审核的扩大训练集，沿用 R46 通用 System 与训练参数 | 验证“更好的训练数据”是否改善文笔/剧情而保持玩家控制权 | 需新 GPU 授权 |
| v0.3-B（条件可选） | 在同一已准入训练集上试验单独的 System 合同调整 | 分离 Prompt 效果，不污染 v0.3-A 因果解释 | 非必需；需再授权 |
| v0.3-C（暂缓） | 调 LoRA rank/epoch/lr | 只有 A/B 证据不足且预注册改动时才启动 | 不自动执行 |

### 固定模型与训练超参（v0.3-A 初始建议）

- `Qwen/Qwen3.8-27B` pinned revision `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`.
- ms-swift `4.5.3`, transformers `5.16.1`, bitsandbytes `0.50.2`，记录 PyTorch/CUDA、tokenizer 和模板哈希。
- QLoRA：NF4 4-bit、BF16、rank 64、alpha 128、dropout 0.05、target `all-linear`.
- `max_length=16384`、`loss_scale=last_round`、`disable_ignore_empty_think=true`、`add_non_thinking_prefix=false`.
- `per_device_train_batch_size=1`, gradient accumulation 8, initial learning rate 5e-5, **1 Epoch**. 沿用当前可审计保存/评估策略。
- 禁止因新 Held-out 表现临时改变参数后对同一封存 Held-out 反复提交“首次测试”。

**System Prompt 的公平性问题：**R46 的训练采用通用无角色卡 System，而旧 v0.1 Test 把完整故事卡放在 System 中。R56 必须预先选择**部署合同**（例如统一通用 System + 显式提供故事和角色背景作为独立上下文），全部四模型使用**同一精确输入**。可做“有卡/无卡”敏感性分析，但要预先写明两个独立报告与主要指标，不能事后只挑有利的一套。

## 6. R53：GPU 前 CPU 准入清单

**全部 PASS 才可申请 GPU 预算。** 检查项：

- 新 Train、Val 文件及源证据 SHA256、数量、目标顺序、抽样世界覆盖。
- 全量训练实例原文/派生目标哈希；别名连通分量图；Val 不与 Train/新 Test/已曝光 Test 混淆。
- `max_length 16384` 下实际 Qwen 模板 token 长度与裁剪证据；全部训练目标的最后 Assistant 标签准确计数，历史/System/User 不监督。
- 真实安装的 ms-swift **actual collator / actual model template** 验证，而不仅 Python 静态检验。
- 关键 10–20 个源历史案例的行为一致性 spot-check 和风险闭环，失败不自动改 Gold。
- 生成任务唯一 `RUN_KEY`、HF 私有 Bucket staging prefix、代码/配置 SHA256、A100 VRAM/磁盘/缓存可行性；禁止覆盖 R46 结果。
- 全仓普通 CI（至少部署关键代码的 Ruff/pytest）状态明示，若通用 CI 仍红，禁止将其伪称 PASS；对风险不相关的历史 lint 允许单独标注隔离，但正式训练要有明确的审计例外。
- 记录单次 A100 费用上限、硬超时及用户授权范围；**不在计划阶段提交 Job**。

## 7. R54：单次受控 GPU v0.3-A 实验

**只有用户明确指令并指定本轮收费权限后才执行。** 使用私有 Hugging Face `adradar` 和 `hf://buckets/adradar/storyforge-training`，独立实验目录 `experiments/v03-a/<RUN_KEY>/`（**拟新建**），绝不覆盖 v0.1/v0.2 Checkpoint。

推荐单张 A100 80GB，沿用已经实际可运行的 4-bit BF16 rank64 路线，设置**120 分钟硬超时（建议上限，非耗时预测）**。提交前再次确认 HF 最新计费单价、GPU 是否可用及必要额度；同一次授权只允许一次计划中的 Job，失败先诊断，不自动重跑。

远端执行顺序：输入哈希门禁 → actual collator → GPU VRAM 门禁 → 单 Epoch `swift sft` → train/val Loss 与 trainer_state → Adapter/optimizer Checkpoint 保存 → Adapter reload + 1 条无 Gold 的推理 → 产物清单与 SHA256。仅当以上符合实验合同才报告 `V03_EXPLORATORY_GPU_ENGINEERING_PASS_NOT_PROMOTED`。

**产物保留：** 训练/验证样本文件的私有远端路径，版本化配置和代码，日志、loss 曲线、epoch/global_step、显存峰值、Adapter weights+SHA256、对应基座 revision、运行时长与账单记录（账单如未提供必须标未知）。普通 Git 只存脱敏摘要/哈希/校验脚本，不提交大权重或故事原文，不新增 LFS。

## 8. R55：开发集评测，不动新封存 Held-out

## 9. R56：一次性正式新独立 Test

**必须先有已封存且未用于数据选择或模型迭代的 R50 数据。**

### 9.1 测试合同

四臂候选：Base、v0.1、当前 v0.2 和预先选定的 v0.3-A（也可事先减少为三臂，但不能看结果后改）。Gold 如果没有用户提供原始目标，则 **不临时伪造 Gold**，只做三个/四个模型的同题盲审。

- 统一同一 base revision、System+背景供给方式、上下文裁剪、采样温度、seed、max_new_tokens（首选延续旧 R47 `temperature=0`, `seed=42`, `max_new_tokens=1536`;若产品实际使用随机采样，另建预注册的重复采样子试验）。
- 独立 GPU 推理（需收费批准）；严格 `sample_id` 和输入消息 SHA 匹配；任何丢失、错位、输出空白都 fail closed。
- 每题模型回复独立随机化 A/B/C/D；生成 3 份独立 reviewer CSV，协调员私有答案键绝不暴露；评审者不知模型身份和前几轮答案。
- 评分维度延用剧情连续性、角色一致性、指令遵循、文学表现力、互动推进、玩家自主权 1–5，以及整体偏好、逐字证据、严重问题。
- 先收齐 → 完整性/原文核验 → 三份评分 SHA 冻结 → 独立证据争议审计 → **最后**解盲。
- 报告每个世界组件分数，统计不确定性按**故事/世界分组**估计而不是将 3 个 Reviewer × 60 题当成 180 独立样本；样本只有 4–6 个世界时应说明跨世界不确定性依然很大。

### 9.2 提议预注册的模型晋升门槛（待用户接受才生效）

**质量门槛（候选 v0.3-A vs 冻结 v0.2，辅助看 Base/v0.1）：**

1. 在**每题多数评审**的两两 v0.3-v0.2 偏好比较中，非平局胜出占比 **>50%**，且 95% 世界分组不确定区间不应清晰地支持劣于 v0.2；若区间覆盖持平，应标 `INCONCLUSIVE`，不得声称统计明确优越。
2. v0.3 总六维平均分高于 v0.2，且文学表现力和互动推进**均不低于** v0.2；不能通过牺牲玩家自主权换文笔得分。
3. **严重玩家自主权**：经独立仲裁确认的题级严重侵犯 **≤5%**（示例 40 题≤2、60 题≤3），并且不高于 v0.2；一个模型若存在多人认为严重的行为，即使总体最高分也单独进入 HOLD。
4. **长程禁句/硬事实错误**：明确、逐字、可确定违反的硬禁句案例容忍值建议 **0**；其他关键历史身份/世界状态硬错误也应单独逐题记录。任何确认出现的此类失败须 `BLOCK_OR_HUMAN_OVERRIDE`，不得用总分平均掩盖。
5. 样本覆盖：不少于 4 世界、全部题目和评分完整、模型版本及配置核对 PASS，审稿人身份与历史暴露状态按证据实际披露。

这是一组**建议阈值**，不是 R48 已经使用过的阈值，更不是通过率保证。特别是 40–60 题、4–6 世界，对小幅提升的置信度仍可能不足；**证据不足本身就是可接受的结论**，不得强行晋升。

### 9.3 Release / HOLD / FAIL

- `PASS_FOR_SCOPED_RELEASE_REVIEW`：全部样本/来源/隔离/技术门槛通过，质量改进和硬错误门槛也通过，仍需项目所有者最终批准发布。
- `INCONCLUSIVE_NO_PROMOTION`：趋势有改善但缺足够新故事覆盖/统计信心，或无法达成人工审稿一致。
- `FAIL_NO_PROMOTION`：质量明显下降、严重越权超过门槛、硬禁句确认违规、来源/隔离出错。
- 每一种结果都保留新题答案及评分完整性证据，所有 GPU 产物保持私有；失败后这批测试已暴露给训练决策者，不得被再次当作“首用独立 Held-out”。
